# 그림 전사 — 공통 함정 (배치 간 누적)

> 2026-09-03 충실도 감사(112건 전수, `docs/claude/2026-09-03-그림-전사-충실도/defects.md`), 09-05 손 전사 773건,
> 09-06 재전사 256건·판정관, 09-15 MCP 전사 4건에서 **그림 종류를 바꿔도 다시 나온** 함정만 모은다.
> 어휘(요소·필드)의 정본은 `figure_transcribe_read` 의 `rules` 다 — 여기는 "그 규칙을 알고도 틀린 곳" 목록이다.
> 새 배치에서 같은 유형이 또 나오면 한 줄 추가한다(F-번호 이어서).

## 크기·좌표

- **F-1** math 좌표(A)의 `canvas`는 원본 픽셀 크기(`imageSize`)에서 만든다. image 좌표(B/C/D)는 서버의 정규화 canvas를 따르고 원본과 같은 표시 폭으로 비교한다. 추측한 비율은 그림을 왜곡한다
  (감사 6건). 렌더 CLI 에도 같은 값을 `--size` 로 준다.
- **F-2** 좌표는 눈대중이 아니라 **픽셀 실측**으로 — 원본에서 꼭짓점·교점 위치를 재서 옮긴다. 비율 왜곡·좌표 뒤집힘의 원인.
- **F-3** 좌표평면 눈금은 손 `label` 대신 `axes.xTicks/yTicks` 를 우선한다 — 원점 근처에 손 라벨이 몰리면 밀려 오독된다(882).

## 빠뜨리기 쉬운 것 (요소 누락 26%)

- **F-4** **음영**은 `region`(solid/difference/intersection)으로 — 감사에서 누락 1위였다. 원·다각형 경계는 된다.
- **F-5** 축·대응 다이어그램의 **화살촉**(`segment.arrow`) — 재전사에서 50건+ 고쳤다.
- **F-6** 치수 중괄호·치수 표시는 곡선/점선 조각으로 흉내 내지 말고 `dim`.
- **F-7** 집합 벤다이어그램의 **타원**을 `circle` 로 그리지 않는다 — 닫힌 `arc` + `ry`(감사 10건).
- **F-8** 곡선(포물선·호)을 각진 선분으로 근사하지 않는다 — `curve`/`arc`.
  식을 모르는 곡선은 `spline`을 쓴다. 축과 만나는 끝이 가파르면 **끝점 바로 안쪽의 점도 실측**한다.
  원본과 렌더의 절편이 같아도 축에 닿는 방향이 다르면 보정한다(문항 #16023).
- **F-9** 입체도형(원기둥·원뿔)의 뒤쪽 밑면은 점선 반 타원 `arc` + `ry` — 어휘가 **있다**. 유료 vision 이 스스로 포기한 5건은
  프롬프트가 안 먹은 것이지 어휘 구멍이 아니다(09-15).

## 넣지 말 것

- **F-10** 원본에 없는 점·직각 표시·보조선을 더하지 않는다(요소 추가 3%). 확신 없으면 뺀다.
- **F-11** 원본 아래 답 입력칸·폼 UI·끌어놓기 UI 캡처는 옮기지 않는다(916) — 그림 부분만, UI 캡처뿐이면 `unsupported`.
- **F-12** 크롭이 잘려 정답상 있어야 할 요소가 원본에 없으면(2088·2089·2092 — 약수 벤다이어그램의 `1`) **원본대로** 전사하고
  「확인 요청」에 남긴다. 지문·정답으로 추론해 지어내지 않는다.

## unsupported (억지로 그리지 않는다)

- **F-13** 회화적 삽화(벽돌담·꽃밭·사진)·색·음영이 뜻을 갖는 표는 `unsupported` — 원본 PNG 가 그대로 나가므로 잃는 것이 없다.
  **조립제법·수직선 같은 선+글자 배치는 rules 의 D 유형이라 옮긴다**(`coords:"image"` 의 segment·label — 2026-10-19 잡 130 4번 통과). 옛 "조립제법 표 unsupported" 는 폐기.
  억지 전사는 오히려 오도한다(감사 1건).
- **F-14** **곡선 경계 사이 색칠**(`y=3ˣ` 와 `y=3ˣ+3` 사이 등)은 지금 어휘로 안 된다(`region.shapes` 는 원·다각형·중첩만,
  경계 좌표 직접 계산도 규칙상 금지) — `unsupported`, 사유 `curved-region`. 2~3% 라 어휘 확장은 보류(B안, 09-15).
- **F-15** 가로로 긴 다중 패널(3패널 등)은 렌더러 폰트 스케일이 캔버스 폭 기준이라 라벨이 뭉친다(1927~1929) — 렌더 대조에서
  뭉치면 `unsupported`, 사유 `multi-panel`.

## 표기

- **F-16** 라벨은 원본 글자 그대로, 수식은 LaTeX. 분수는 `\frac{a}{b}`(평문 `a/b` 금지 — 감사 5건).
- **F-17** 점선/실선을 원본에 맞춘다 — 치수 호가 직선 점선으로 바뀐 사례(감사 16건).
  그래프는 주 곡선·축·경계선·보조선의 상대 굵기도 각각 잰다. 원본의 굵은 주 곡선은 `strokeScale`로 살리고, 기하 좌표와 점선 여부를 유지한다.

## 판정 기준 (판정관)

- **그래프 눈금**은 원점과 축의 기준 눈금을 맞춰 비교한다. 글자와 지시선을 따라가며 지시선의 축 쪽 끝이 원본과
  같은 눈금에 닿는지 확인한다(#16059). 원이 포함된 수학 좌표 그래프는 `axes`를 우선 쓰고, 원점 O가 접점을 가리지 않는지 본다(#16063).
- 음영 이름이나 조밀한 눈금이 자동 배치에서 밀리면, 현재 DSL 명세가 지원하는 경우 독립 `label`에
  `placement: "fixed"`를 준다. 원본에서 잰 글자 중심과 정렬을 유지하고 같은 표시 크기에서 영역 이탈·겹침·잘림을 대조한다(#8732·#16060).
- 글자 높이는 기준 눈금 두 개 또는 같은 변 길이로 배율을 맞춘 다음 잰다. 전체 글자 크기는 원본 크롭의 `source.glyphPx`를 확인하고, 일부 글자만 다르면 `fontScale`을 조절한다. 고해상도 크롭에서 잰 높이는 저장된 원본 폭 비율로 환산한다(#16028).
- 현재 DSL 명세가 지원하면 B처럼 원본에서 직립인 점 이름에 `fontStyle: "upright"`를 쓴다. x·y 같은 수학 변수는 기본 수식 글꼴을 쓴다. 원본이 선 겹침을 의도한 라벨은 `lineOverlap: "allow"`를 쓰고, 분리해야 할 고정 글자에서 경고가 뜨면 위치를 재측정한다(#16046).

- **F-18** `approve`는 **관계가 정확하고 실제 크기에서 읽히는 그림**이다. 픽셀 일치는 필요 없지만 글자 배경이 선을 지우거나
  수치가 다른 변에 붙어 읽히면 통과시키지 않는다. 코드로 고칠 수 있으면 `fix`, 렌더러 문제면 원본 유지/표시 확인 대기로 보고한다.
- **F-19** 문제를 푸는 데 필요한 정보(값·라벨·관계)가 렌더에서 틀리거나 빠지면 `fix`. 어휘로 못 그리는데 렌더가 원본을
  오도하면 `keep_original`. 자신 없으면 `keep_original`.

## 운영

- **F-20** MCP 검증 실패는 `FAILED` 로 굳지 않는다 → 건너뛴 그림은 목록 맨 앞에 남는다. 다음 묶음은 **직전 묶음의 마지막
  assetId 를 `afterAssetId`** 로 넣어 받는다. 커서 없이 부르면 같은 그림만 계속 돌아온다.
- **F-21** 렌더 CLI 는 윈도우에서 `--headless=new` 로만 찍힌다(옛 모드는 PNG 없이 끝남, 2026-10-10 수정됨). Chrome 이 비표준
  위치면 `CHROME_PATH`.
- **F-22** 라벨에 `/` 가 있으면 렌더러가 **라벨 전체**를 분수로 조판한다(`y=x²/2` → `(y=x²)/2`, `a^{x⁄2}` 는 분수선이 빠져
  `a^{x2}`). rules 의 "분수는 x/2" 와 어긋나므로 계수는 `½x²`, 지수는 `a^{½x}` 처럼 유니코드 분수로 쓰고 렌더로 확인한다
  (2026-10-10 배치 2241·2554).
  → **렌더러 수정(2026-10-10, 커밋 후 배포부터)**: `=`·`<`·`>`·`≤`·`≥`·`≠` 앞은 본문으로 떼고 뒤만 분수로 조판한다 — 배포 뒤엔
  `y=x^2/2` 를 그대로 써도 된다. **지수 안 분수(`a^{x/2}`)는 여전히 깨지니** 계속 `a^{½x}` 로. (888a35b2 배포됨)
- **F-23** 서브에이전트의 `figure_transcribe_apply(dryRun:false)` 는 auto mode 분류기가 막을 수 있다(같은 배치에서 2명 통과·1명
  차단). 적재는 사용자 승인 뒤 **메인이 직접** 부른다. dryRun 도 `dryRun:true` 를 명시해야 덜 막힌다.
- **F-24** 독립 `label` 텍스트가 식(`y=1`, `x²+y²=10`)이면 렌더러가 그 식에 맞는 선을 찾아 라벨을 옮긴다 — 라벨이 뒤바뀐 선에
  붙거나(2258) 다른 선분을 잘라 그린다(2793). 식은 해당 `curve`·`circle`·`segment` 의 `label` 에 넣고, 독립 라벨이어야 하면
  전각 `＝` 로 쓴다(2026-10-10 2배치).
  → **렌더러 수정(206e4c61, 다음 배포부터)**: 선분도 중간 점까지 식에 맞는지 보고, 자리가 있으면 캡션을 선 끝 연장선에 둔다 —
  배포 뒤엔 독립 식 라벨을 그냥 써도 된다(전각 우회 불필요). 배포 전 배치는 위 우회 그대로.
- **F-25** 자동 눈금 라벨·`O` 의 흰 테두리가 근처를 지나는 선을 지워 끊겨 보인다(2574). F-18 "렌더러 몫"으로 넘기지 말고 그
  눈금을 `xTicks`/`yTicks` 에서 빼 원본 위치의 `label` 로 옮긴다. `O` 가 옆 기호 라벨을 밀어 부호가 바뀌어 보이는 경우(2578)도 같다.
  → **렌더러 수정(206e4c61, 다음 배포부터)**: 눈금값·`O` 가 지나가는 실선·곡선을 피한다 — 배포 뒤엔 눈금을 손 라벨로 옮길 필요 없다.
  남은 것: **원 테두리**는 여전히 지워질 수 있고, 2578 의 `O` 밀어내기는 그대로(손 라벨 우회 유지).
- **F-26** 잔 한계: `region.shapes` 는 8개까지(넘으면 거부 — 윤곽 polygon 1개로) · 이미지 좌표 polygon 점이 캔버스 밖이면 거부
  (클리핑) · `⁄`(U+2044)는 렌더에서 안 보임 → `∕`(U+2215) · 아래첨자 문법 없음(`log_b` 그대로 찍힘).
- **F-28** F-22 렌더러 수정(888a35b2 배포) 뒤에도 남은 분수 함정: `y=x²+3/4` 처럼 식 뒤 `+분수` 는 `(y=x²+3)/4` 로 묶이고(2603),
  독립 label `y=2/3` 은 x축 근처로 옮겨진다(2288). 상수 분수는 `¾`·`⅔`, 독립 식 라벨은 전각 `＝`. `segment.label` 에 `y=x` 를
  넣으면 선분 한가운데에 찍힌다 — 끝에 둘 식은 독립 label.
  → **렌더러 수정(a99d7b8f, 다음 배포부터)**: 분수는 `/` 바로 앞 **한 항**만 분자(`y=x²+3/4` OK, `(x+1)/2` 는 통째로) — 배포 뒤엔
  `¾` 우회 불필요. `y=2/3` 위치 이동(2288)은 F-24 수정으로 함께 풀렸는지 배포 뒤 첫 배치에서 확인.
- **F-29** `angle.label` 이 겹침을 피하다 호의 반대편으로 갈 수 있다(2296). 원본 위치가 중요하면 angle 라벨을 빼고 독립 `label` 로.
- **F-27** 병렬 전사관은 scratchpad 를 같이 쓴다 — 보조 스크립트·임시 파일 이름에 **구분 문자를 붙인다**(`ap_A.py`). 같은 이름을
  쓰다 A 의 줄이 B.jsonl 에 섞였다(2026-10-10 2배치, 정리됨).

- **F-30** 색계열뿐 아니라 색면의 위치·빈 영역·입체 각 면을 대조한다. 기본 검정과 구별되는 회색 보조선도 `color`로 유지한다.
- **F-31** 단독 PNG는 맞아도 여러 인라인 SVG의 ID 충돌로 화면 색칠이 틀릴 수 있다. 저장 후 같은 실제 화면에서 함께 확인한다.
  개별 렌더와 화면이 다르면 좌표·색상 값을 계속 바꾸지 말고 렌더러 문제로 보고한다([review.md](review.md)).
- **F-32** 재검수는 현재 문서·원본 파일을 확인하고 같은 assetId 또는 jobId/index를 고친다. 옛 PDF 경로 재사용·새 이력 생성 금지.
- **F-33** 코드 전사와 원본 유지를 따로 세고 사유를 보고한다. 실제 표시를 못 봤으면 미확인으로 남긴다. 원본 폴백을 위해
  코드를 비울 때는 먼저 이전 코드·대상·사유·복원 조건을 보존하고 `hasFigure`·원본 크롭을 유지한다.
- **F-34** 렌더 라벨 글꼴이 원본보다 커서 원본처럼 좁은 틈(호와 선 사이·치수 곡선과 모서리 사이)에 둔 라벨은 흰 배경이 선을 지운다 — 독립 `label` 도 같다. 라벨을 틈 밖으로, 선에서 글자 높이 반 이상 뗀다(2026-10-22 재검수: 15·18·31·65·66·72).
- **F-35** 재검수 중에도 사람이 검수 화면에서 승인(READY)할 수 있다 — 저장 직전에 `mode:"retranscribe"` 로 대상이 아직 DRAFT 인지 다시 본다. READY 가 된 그림의 남은 차이는 보고만 한다(2026-10-22: 65 보정 코드 보관만).
- **F-36** 독립 label의 y는 글자 묶음의 세로 중심이고 x는 anchor 기준이다. 원본 점 좌표/베이스라인과 혼동하면 축 아래 글자·점 이름이 어긋난다. 함수식의 자동 끝 배치도 원본의 캡션 위치를 보장하지 않는다 — 원본과 같은 쪽·정렬·간격을 각각 확인한다(2026-10-23 검수 대기 22건).
- **F-37** math 좌표(A)의 작은 canvas와 누락된 source.glyphPx가 함께 있으면 로컬 렌더와 MCP 저장 후 글자 크기가 달라진다. A는 원본 imageSize 크기, image 좌표(B/C/D)는 서버 정규화 canvas를 사용한다. 제공된 glyphPx를 보존하고 저장 후 코드를 다시 읽어 원본과 같은 표시 폭으로 확인한다. 기하나 view를 늘려 라벨을 맞추지 않는다.
- **F-38** 추출 잡의 llmModel은 그림 전사자의 증거가 아니다. 배치 산출·백업에서 직접 확인한 작성 주체와 이번 수정 주체를 구분해 기록하고, 기록 없는 최초/최종 전사자는 미확인으로 남긴다.
- **F-39** image 좌표(B/C/D)를 0~1000 이 아니라 원본 픽셀 단위로 적어도 렌더러의 내용 맞춤(fitView)이 가려 렌더 대조로는 안 잡힌다(2026-10-24 자산 336). 좌표 범위가 0~1000 인지 따로 본다.
- **F-40** `source.glyphPx` 8 같은 작은 값은 오측일 수 있다(실제 대문자 약 12 — 2026-10-24 155·158). 하한 9 아래라 렌더러가 버려 기본 크기가 되는데, 이걸 "원본보다 크다"고 보고 `fontScale` 로 줄이면 실제 화면에서 글자가 원본의 절반이 된다. 글자 크기 처방은 단독 PNG 가 아니라 **실제 검수 화면에서 칸 높이 대비 글자 비율**로 판단한다. 기본 크기에서 빠듯한 표 행 글자가 밀려나면 렌더러 한계 — `keep_original`.
- **F-41** MCP `figure_render` 서버 PNG 는 캔버스 높이가 낮은(약 135 이하) 그림에서 아래가 잘리고 아래첨자(ₙ₊₋)가 두부로 찍힌다. 검수 화면(서버 SVG 를 img 로 표시)은 정상이다(2026-10-24 114·152·184). 이 둘에서는 판정을 화면으로 한다.

- **F-42** 집합 이름 A·B·C·X·Y는 원·타원 외곽선 위에 걸쳐 놓는다. 꼭대기는 해당 circle/닫힌 arc의 label, 옆·아래는 원본 방향의 외곽선 위 독립 label(anchor:middle)로 적고 같은 이름을 중복하지 않는다. 원소 숫자·영역 글자는 내부에, U는 상자에 유지한다. F-34의 선 회피 때문에 집합 이름을 안쪽/상자로 밀지 않는다. 흰 halo는 렌더러가 맡으며 색면 위 이름도 실제 크기로 확인한다(자산464).

- **F-43** 표의 칸 중심 x를 적었으면 anchor:middle을 명시한다. 기본 start에 맡기면 글자 폭 때문에 옆 열로 밀린다(352). 행 y는 같은 세로 중심으로 맞추고, 바깥 세로선이 생략된 표도 원본의 행·열 위치를 보존한다. 최신 렌더러는 같은 폭의 가로선3개 이상과 내부 열선이 있을 때 생략한 바깥 경계도 셀로 취급한다.
