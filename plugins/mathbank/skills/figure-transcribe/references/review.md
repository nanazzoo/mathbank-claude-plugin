# 재전사·원본 대조·실제 표시 확인

기존 그림을 다시 보거나 등록 전 초안의 그림을 보완할 때 먼저 이 문서를 읽는다. 신규 그림도 아래 품질 기준과 완료 보고를 따른다.

## 대상과 원본 확인

| 대상 | 읽기 | 쓰기 |
| --- | --- | --- |
| 등록 문항의 코드 없는 그림 | `figure_transcribe_read(mode:"missing")` | `figure_transcribe_apply` |
| 등록 문항의 DRAFT·FAILED 재전사 | `figure_transcribe_read(mode:"retranscribe")` — 이전 코드·사유도 확인 | 같은 assetId에 `figure_transcribe_apply` |
| 등록 전 추출 이력 | `extract_job_get(jobId, mode:"all")`로 항목과 기존 코드 확인, `extract_pages_read`로 해당 원본 쪽 확인 | 같은 jobId·index에 `extract_job_items_update` |
| 사람이 승인한 READY 그림 | `problem_figures_read`로 원본과 현재 그림 확인 | 이 스킬에서 덮어쓰거나 READY로 승인하지 않는다. 차이를 보고한다 |

- 재검수만 하려고 새 추출 잡을 만들거나 문항을 등록하지 않는다. 부분 등록된 잡은 미등록 항목만 잡 경로로 고친다.
- `document_get`의 현재 문서명·원본 파일을 확인한다. 예전 문서 번호·교재명·로컬 PDF 경로를 재사용하지 않는다. 벡터 초안은 현재 문서와 같은 파일·쪽임을 확인한 경우에만 쓴다. 로컬 파일이 없으면 MCP 이미지로 전사한다.
- 원본 크롭과 전체 쪽을 함께 보고 그림이 잘리거나 본문·답칸이 끼었는지 확인한다. 원본이 잘린 경우 추론으로 요소를 채우지 않는다.
- 그림만 고칠 때 지문·정답·해설·aiCheck·다른 항목은 유지한다. 크롭 수정이 필요하지 않으면 `hasFigure`·`figureBox`도 유지한다.
- 저장은 dryRun으로 변경할 항목·칸을 확인한 다음 메인이 한다. 이미 요청·승인된 보완 범위는 다시 묻지 않는다. 저장 뒤 재조회해 대상 코드와 원본이 유지됐는지 확인한다.

## 원본 ↔ 코드 검수

1. **색**: 색면마다 색계열·채운 위치·빈 영역·앞/위/옆면 구분을 대조한다. 기본 검정과 구별되는 회색 보조선도 보존한다. 원본의 평평한 면 안쪽을 기준으로 보고 스캔 잡음·테두리 픽셀까지 일치시키려 하지 않는다.
   빗금이 있으면 같은 축 간격 또는 변 길이에서 빗금 사이 간격과 굵기도 대조한다. 현재 DSL 명세가 지원하면 `hatchScale`로 간격을, `strokeScale`로 빗금 굵기를 조절한다(#16028).
2. **선**: 실선·점선·숨은 모서리·치수선·호를 하나씩 대조한다. 점선이 실제 표시 크기에서도 보이고, 선 끝이 교점·꼭짓점에 닿는지 확인한다.
   주 곡선, 축, 경계선, 보조선의 굵기를 같은 배율에서 대조한다. 원본에서 굵게 강조한 선은 `strokeScale`로 살린다.
3. **글자와 수치**: 값·이름의 개수, 각 값이 가리키는 변·점, 직각·화살표 방향을 대조한다. 글자의 배경이 도형을 지우거나 숫자가 옆 변에 붙어 읽히면 통과시키지 않는다. 기하 좌표를 왜곡하지 말고 지원되는 라벨 위치·정렬·치수 offset으로 보정한다.
   그래프는 원점과 기준 눈금을 맞춘 뒤, 곡선이 절편에 접근하는 방향도 본다. 눈금과 떨어진 글자는 지시선을 따라가 축 쪽 끝이 원본과 같은 눈금에 닿는지 확인한다.
   같은 기준 눈금 간격이나 같은 변 길이에서 대문자·숫자의 높이와 중심 위치를 잰다. 원본에서 붙은 표기와 렌더 때문에 새로 선에 걸친 표기를 구분한다. 좌표축의 수학 변수와 직립 점 이름 글꼴도 따로 대조한다. 편집기의 겹침 경고는 확인할 위치를 알려 준다. 화면과 인쇄 크기에서 실제로 선이 글자를 지나는지 확인한다.
   - 독립 `label`의 y는 글자 묶음의 세로 중심이다. x는 `anchor`의 왼쪽/가운데/오른쪽 기준으로 측정한다. 점 위치나 베이스라인과 혼동하지 않는다.
   - 원본의 어느 쪽에 붙어 있는지까지 확인한다. 축 이름·O·눈금·점 이름·함수식은 각각 확인하고, 표는 행의 세로 중심·열의 가로 기준을 맞춘다. 자동 배치 성공만으로 같은 위치라고 판단하지 않는다.
   - math 좌표(A)의 `canvas`는 원본 크기와 맞춘다. image 좌표(B/C/D)는 서버가 정규화한 canvas를 따르고 원본과 같은 표시 폭으로 비교한다. 로컬 코드의 `source.glyphPx`에는 제공된 `imageSize.glyphPx`를 보존한다. 저장 과정에서 글자 높이가 달라지면 저장 후 재조회한 코드로 다시 렌더한다. 기하/view를 바꾸어 라벨 공간을 만들지 않는다.
4. **집합 이름**: A·B·C·X·Y가 원·타원 외곽선 위에 걸쳐 있고 중복되지 않는지 확인한다. 숫자·영역 글자·U는 원래 역할과 위치를 유지한다. 이름이 내부로 밀리거나 선과 겹쳐 읽히지 않으면 보완한다.
5. **입체·복잡한 그림**: 색·광택을 억지로 단순화해 원본과 다른 인상을 주면 `keep_original`. 원본 유지도 유효한 결과지만 코드 전사 성공으로 세지 않는다.

판정은 픽셀 일치가 아니라 **관계가 정확하고 실제 크기에서 읽히는가**다. 의미와 가독성을 해치지 않는 미세한 위치 차이는 허용한다. 가림·오독은 렌더러 탓이어도 승인 사유가 아니다. 코드로 고칠 수 있으면 `fix`, 표현 한계나 표시 오류가 남으면 `keep_original` 또는 표시 확인 대기로 기록한다.

## 단독 렌더와 실제 화면은 별도 확인

- 승인 전 판정은 `figure_render({assetId})`(code 없이 — 저장된 코드를 서버가 적재 때와 같은 크기·glyphPx 로 다시 그린 그림)로 한다. 로컬 렌더·접촉 시트는 저장 전 미리보기다(2026-11-19 결정 1).
- `figure_render`·접촉 시트는 개별 코드 검증이다. 통과한 뒤 저장된 코드를 다시 읽고, 배치에서 여러 그림을 같은 실제 검수 화면에 표시해 대조한다. 색칠 그림이 여러 개면 함께 표시하고 원본·코드가 나란히 보이도록 한다.
- 색칠 면·라벨 밀집·점선이 있는 그림을 실제 표시 크기에서 확인한다. 같은 화면에서 SVG의 마스크·그라데이션 ID가 중복되거나 다른 SVG를 참조하면 표시 오류다.
- 개별 PNG는 맞는데 화면에서만 어긋나면 색상 값·기하 좌표를 계속 바꾸지 않는다. 메인에게 **렌더러 문제**로 보고하고, 코드와 근거를 보존한다. 앱 수정·배포는 이 스킬 밖의 별도 작업이며 MCP 데이터 저장과 구분해서 설명한다.
- 브라우저를 사용할 수 없으면 `실제 표시 미확인`으로 남긴다. 코드 검증을 실제 화면 검증 완료로 보고하지 않는다. 미확인이어도 판정관이 `figure_render({assetId})` 로 approve 한 그림은 승인 목록(`figure_approve` 대상)에 넣는다(2026-11-19 결정 — 에이전트는 대개 브라우저가 없다).

## 원본 유지와 보고

- 등록 자산은 DRAFT 상태와 원본 PNG를 보존한다. 등록 전 잡에서 잘못된 미리보기를 원본으로 돌리려고 `figureCode:null`을 써야 하면 먼저 jobId·index·이전 코드·사유·복원 조건을 검토 기록에 남긴다. `hasFigure`와 원본 상자는 유지한다. 지원하지 않는 상태·사유 필드를 MCP 요청에 발명하지 않는다.
- 검토 기록에는 식별자(jobId/index 또는 problemId/assetId), `코드 검증`, `실제 표시 확인`, `코드 사용/원본 유지`, 사유를 따로 적는다. 이는 로컬 검토 기록이며 DB 스키마를 추가하라는 뜻이 아니다.
- 재검수 기록에는 수정 전후 코드와 이번 작업 주체·방식·규칙 버전도 남긴다. 원래 추출 잡의 모델/수동 여부와 그림의 최종 전사자는 구분한다. 자산에 작성자 기록이 없고 배치 산출로도 확인되지 않으면 `최종 전사자 미확인`으로 적는다.
- 최종 보고 예: `대상 그림 6개 / 보정 코드 5개 / 원본 유지 1개(입체 광택) / 실제 표시 6개 확인 / 이력 1개 유지·등록 전`.
- 실제 표시를 못 봤으면 `코드 검증 5개 완료·실제 표시 미확인`이라고 명시한다. `keep_original`은 승인 목록(`figure_approve` 대상)에서 제외한다. 미확인은 제외 사유가 아니다.
